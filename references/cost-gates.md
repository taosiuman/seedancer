# 成本门禁协议 v1.0

> 借鉴 ShotFunClaw `workflow-runtime.js` 的 `withCostGuard` 设计

---

## 核心原则

在执行任何付费操作前，必须进行成本预估和确认，避免意外消耗。

---

## 1. 成本预估流程

### 1.1 预估步骤

```
1. 统计步骤数量
   - 图片生成次数
   - 视频生成次数
   - 音频生成次数

2. 查询模型价格
   - 从模型映射表获取单价
   - 确认币种（积分/元）

3. 计算预估成本
   - 总成本 = Σ(数量 × 单价)
   - 考虑重试次数（默认 +20%）

4. 输出成本报告
   - 展示明细
   - 等待用户确认
```

### 1.2 成本报告模板

```markdown
## 成本预估报告

**项目**: <项目名>
**执行模式**: <快速/标准/完整>
**预估时间**: 2026-09-10 10:30

### 步骤明细

| 步骤 | 模型 | 数量 | 单价 | 小计 |
|------|------|------|------|------|
| 图片生成 | GPT Image 2 | 5 | 55积分 | 275积分 |
| 视频生成 | Seedance 2.5 | 10 | 250积分/秒 | 2500积分 |
| 音频生成 | MiniMax TTS | 3 | 30积分 | 90积分 |

### 总计

- **预估总成本**: 2865积分
- **实际成本**: 待生成后回填
- **确认状态**: 待确认

### 成本控制

- 预算上限: 3000积分
- 剩余预算: 135积分
- 风险提示: ⚠️ 接近预算上限
```

## 2. 成本确认策略

### 2.1 自动确认（无需用户确认）

**适用条件**: 预估成本 < 5积分

**执行流程**:
```
1. 输出成本报告
2. 直接执行
3. 记录实际成本
```

**示例**:
- 单张图片生成（55积分）
- 单次音频生成（30积分）

### 2.2 一次性确认

**适用条件**: 5积分 ≤ 预估成本 < 50积分

**执行流程**:
```
1. 输出成本报告
2. 等待用户确认
3. 用户确认后执行
4. 记录实际成本
```

**示例**:
- 批量图片生成（10张 = 550积分）
- 短视频生成（5秒 = 1250积分）

### 2.3 详细确认

**适用条件**: 50积分 ≤ 预估成本 < 100积分

**执行流程**:
```
1. 输出详细成本报告
2. 展示风险提示
3. 等待用户明确确认
4. 用户确认后执行
5. 记录实际成本
```

**示例**:
- 长视频生成（30秒 = 7500积分）
- 批量视频生成（5个 = 12500积分）

### 2.4 分阶段确认

**适用条件**: 预估成本 ≥ 100积分

**执行流程**:
```
1. 输出详细成本报告
2. 拆分为多个阶段
3. 每个阶段独立确认
4. 每个阶段完成后记录实际成本
5. 下一阶段基于剩余预算重新评估
```

**示例**:
- 大型项目（100+视频 = 25000+积分）
- 拆分为：角色资产 → 分镜生成 → 视频生成 → 后期处理

## 3. 成本回填

### 3.1 回填流程

```
生成完成后：
1. 查询实际消耗
2. 对比预估成本
3. 计算差异
4. 更新成本记录
```

### 3.2 回填数据结构

```json
{
  "projectId": "project-001",
  "estimatedCost": {
    "total": 2865,
    "breakdown": {
      "images": 275,
      "videos": 2500,
      "audio": 90
    }
  },
  "actualCost": {
    "total": 2950,
    "breakdown": {
      "images": 275,
      "videos": 2580,
      "audio": 95
    }
  },
  "variance": {
    "total": 85,
    "percentage": 2.97
  },
  "timestamp": "2026-09-10T10:45:00Z"
}
```

### 3.3 差异分析

**差异类型**:
- ✅ 正常差异（<10%）: 无需处理
- ⚠️ 轻微超支（10%-20%）: 记录原因
- ❌ 严重超支（>20%）: 触发审查

**常见原因**:
- 重试次数超出预期
- 模型价格变动
- 生成参数调整
- 意外错误导致重复生成

## 4. 成本控制建议

### 4.1 快速模式

**特点**: 低成本、快速迭代

**策略**:
- 使用低成本模型（Nano Banana 2, Seedance 2.0 Mini）
- 减少迭代次数（最多2次）
- 跳过非关键步骤

**适用场景**:
- 原型验证
- 内部测试
- 快速出片

### 4.2 标准模式

**特点**: 平衡成本与质量

**策略**:
- 使用标准模型（GPT Image 2, Seedance 2.5）
- 适度迭代（最多3次）
- 保留关键步骤

**适用场景**:
- 常规项目
- 客户交付
- 商业项目

### 4.3 完整模式

**特点**: 高质量、高成本

**策略**:
- 使用高质量模型（Kling 3.0 Omni, MiniMax H3）
- 充分迭代（最多5次）
- 保留所有步骤

**适用场景**:
- 重要客户
- 高质量要求
- 预算充足

### 4.4 成本超预算处理

**触发条件**: 实际成本 > 预算上限

**处理流程**:
```
1. 暂停执行
2. 输出成本警告
3. 提供选项:
   a. 增加预算
   b. 切换到快速模式
   c. 减少迭代次数
   d. 取消剩余任务
4. 等待用户决策
```

**警告模板**:
```markdown
## ⚠️ 成本超预算警告

**当前成本**: 2950积分
**预算上限**: 3000积分
**剩余预算**: 50积分
**预计剩余任务成本**: 500积分

### 风险提示

继续执行将超出预算 450积分。

### 可选方案

1. **增加预算**: 调整预算上限至 3500积分
2. **切换模式**: 切换到快速模式，预计成本 1500积分
3. **减少迭代**: 将迭代次数从3次减少到1次，预计节省 300积分
4. **取消任务**: 取消剩余任务，保留已完成内容

请选择处理方案。
```
