# 素材报白流程 v1.0

> 借鉴 ShotFunClaw 素材报白机制（Asset://... 引用）

---

## 核心概念

当 Seedance/Kling 等视频模型使用**真人素材**（照片、视频）作为参考时，必须先将素材"报白"（审核/授权），才能用于生成。

**报白 = 将真人素材转为 `Asset://...` 引用**

---

## 1. 触发条件

### 1.1 需要报白的素材

| 素材类型 | 需要报白？ | 说明 |
|----------|-----------|------|
| 真人照片（人脸） | ✅ 必须 | 包含真实人脸特征 |
| 真人视频（人脸） | ✅ 必须 | 包含真实人脸特征 |
| 真人照片（无人脸） | ❌ 不需要 | 如手部特写、背影、道具 |
| 场景照片 | ❌ 不需要 | 无人脸 |
| 道具照片 | ❌ 不需要 | 无人脸 |
| AI 生成图片 | ❌ 不需要 | 非真人 |
| 插画/卡通 | ❌ 不需要 | 非真人 |

### 1.2 判断规则

```
素材包含人脸？
  ├─ YES → 需要报白
  │   ├─ 检查人脸特征是否清晰可见
  │   └─ 即使模糊，只要"可能"是人脸 → 保守起见，报白
  └─ NO → 不需要报白
          └─ 标记为 face_status: face_free
```

## 2. 报白流程

### 2.1 流程概览

```
用户上传真人素材
  ↓
Agent 判断是否需要报白
  ├─ 需要 → 进入报白流程
  └─ 不需要 → 直接使用
  ↓
创建资产组（Asset Group）
  ↓
上传素材到资产组
  ↓
调用报白 API（创建 Asset 引用）
  ↓
获得 Asset://... 引用
  ↓
后续使用 Asset://... 而非原始 URL
```

### 2.2 详细步骤

#### 步骤 1：判断是否需要报白

```
用户输入：生成视频，使用这张照片作为参考
Agent 行为：
1. 检查照片是否包含人脸
2. 如果需要报白：
   - 输出："检测到真人素材，需要先进行素材报白。"
   - 进入报白流程
3. 如果不需要：
   - 输出："该素材不包含人脸，可以直接使用。"
   - 标记为 face_status: face_free
```

#### 步骤 2：创建资产组

```
Agent 行为：
1. 调用 ShotFun API：创建资产组
2. 资产组名称：如 "project-x-reference-assets"
3. 获得资产组 ID
```

#### 步骤 3：上传素材

```
Agent 行为：
1. 上传素材到资产组
2. 获得素材在资产组中的引用
```

#### 步骤 4：调用报白 API

```
Agent 行为：
1. 调用 ShotFun API：创建 Asset 引用
2. 传入：资产组 ID + 素材引用
3. 等待审核（通常几秒到几分钟）
4. 获得 Asset://... 引用
```

#### 步骤 5：使用 Asset 引用

```
后续所有提示词中：
- ❌ 不使用原始 URL：https://example.com/photo.jpg
- ✅ 使用 Asset 引用：Asset://group-id/asset-id
```

## 3. 资产组管理

### 3.1 资产组结构

```
资产组（Asset Group）
  ├─ 名称：project-x-reference-assets
  ├─ 资产 01：character-01-main (Asset://123/456)
  ├─ 资产 02：character-02-main (Asset://123/789)
  └─ 资产 03：scene-01-keyframe (Asset://123/abc)
```

### 3.2 资产组复用

```
同一项目的多次生成：
1. 检查是否已有资产组
2. 如果有，复用现有资产组
3. 如果没有，创建新资产组
```

### 3.3 资产组命名规范

```
命名规则：<项目名>-reference-assets
示例：
- project-x-reference-assets
- my-short-drama-reference-assets
- brand-video-reference-assets
```

## 4. 与 Seedancer 整合

### 4.1 与 P2a 角色资产整合

```
P2a 角色资产生成流程（增强版）：

1. 用户上传角色参考图
  ↓
2. Agent 判断是否需要报白
  ├─ 需要 → 进入报白流程
  └─ 不需要 → 直接使用
  ↓
3. 如果需要报白：
   a. 创建资产组
   b. 上传素材
   c. 调用报白 API
   d. 获得 Asset://... 引用
  ↓
4. 后续生成角色参考图时：
   - 使用 Asset://... 引用
   - 不使用原始 URL
```

### 4.2 与视频生成整合

```
视频生成流程（增强版）：

1. 构建提示词
  ↓
2. 检查参考素材：
   ├─ 有真人素材 → 必须使用 Asset://... 引用
   └─ 无真人素材 → 可以使用原始 URL
  ↓
3. 提交生成任务
  ↓
4. 如果报白失败：
   - 暂停生成
   - 提示用户："素材报白失败，请检查素材是否合规。"
   - 不静默降级
```

## 5. 报白状态标记

### 5.1 状态类型

| 状态 | 说明 | 处理方式 |
|------|------|----------|
| `face_present` | 明确包含人脸 | 必须报白 |
| `face_possible` | 可能包含人脸 | 保守起见，报白 |
| `face_free` | 不包含人脸 | 不需要报白 |
| `pending` | 报白中 | 等待审核结果 |
| `approved` | 报白通过 | 可以使用 |
| `rejected` | 报白失败 | 不能使用，需要替换素材 |

### 5.2 状态记录

```json
{
  "assetId": "character-01-main",
  "originalUrl": "https://example.com/photo.jpg",
  "faceStatus": "approved",
  "assetRef": "Asset://123/456",
  "assetGroupId": 123,
  "approvedAt": "2026-09-10T11:30:00Z"
}
```

## 6. 失败处理

### 6.1 报白失败

```
报白失败时：
1. 暂停生成
2. 输出："素材报白失败，请检查素材是否合规。"
3. 提供失败原因（如有）
4. 建议用户：
   - 替换素材
   - 或使用不包含人脸的素材
5. 不静默降级（不使用未报白的素材）
```

### 6.2 常见错误

| 错误 | 原因 | 处理 |
|------|------|------|
| `F-ASSET-REJECTED` | 素材不合规（如名人照片） | 替换素材 |
| `F-ASSET-TIMEOUT` | 报白超时 | 重试或联系客服 |
| `F-ASSET-GROUP-NOT-FOUND` | 资产组不存在 | 重新创建资产组 |
| `F-ASSET-UPLOAD-FAILED` | 上传失败 | 检查网络或文件大小 |

## 7. 检查清单

### 7.1 报白前检查

- [ ] 素材是否包含人脸？
- [ ] 是否已创建资产组？
- [ ] 素材是否已上传到资产组？
- [ ] 报白 API 是否可用？

### 7.2 报白后检查

- [ ] 是否获得 Asset://... 引用？
- [ ] 后续提示词是否使用 Asset://...？
- [ ] 是否避免使用原始 URL？
- [ ] 报白状态是否已记录？

### 7.3 生成前检查

- [ ] 所有真人素材是否已报白？
- [ ] 是否有 face_status: face_free 标记？
- [ ] 是否有报白失败的素材？

## 8. 与现有系统的整合

### 8.1 与 P0-P2 预生产整合

在 P2a 角色资产生成前，增加报白检查：

```
P2a 角色资产生成流程：
1. 用户上传角色参考图
2. 🆕 检查是否需要报白
3. 如果需要，执行报白流程
4. 生成角色参考图（使用 Asset://...）
```

### 8.2 与断点续跑整合

当断点续跑时：
1. 检查 manifest.json 中的 assetRefs
2. 验证 Asset://... 引用是否仍然有效
3. 如果失效，重新报白

---

## 9. 注意事项

### 9.1 不要

- ❌ 静默降级（不使用未报白的真人素材）
- ❌ 跳过报白步骤
- ❌ 在提示词中使用原始 URL（应该用 Asset://...）
- ❌ 忽略报白失败（必须暂停并提示用户）

### 9.2 要

- ✅ 明确告知用户需要报白
- ✅ 使用 Asset://... 引用
- ✅ 记录报白状态
- ✅ 报白失败时暂停并提示
