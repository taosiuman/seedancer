# Seedancer v10.0.1 评估报告

> 本报告随 PR 一起提交，记录对技能的整体评估与后续可改进点。本 PR 只落地了**零风险、可自动验证**的部分；涉及 SKILL.md 正文语义的改动列为建议，由维护者决定。

## 一、总体评价

优点：

- **工程化程度高**：19 项一致性检查（版本、链接、索引、锚点、体积预算）+ 攻击测试，在提示词类技能里很少见。
- **硬门思路正确**：台词容量、分组时长、镜头密度都给出了可计算的公式，而不是"尽量"之类的软约束。
- **渐进加载**：主文件 + 48 份 references + 加载表，控制了上下文成本。

主要问题：

1. **公式靠模型心算**。Smin、台词最低时长、组时长上限都是确定性计算，但没有执行工具，模型最容易在这里算错且无法复核。→ 本 PR 已新增计算器。
2. **SKILL.sh 是玩具**。时长/画幅写死为 10s/16:9，忽略用户输入，`--help` 不存在。→ 本 PR 已重写。
3. **没有 CI**。检查脚本只能手动跑，规则再严格也会漂移。→ 本 PR 已新增 workflow。
4. **公式常量只存在于文档**。改了表忘了改别处无人发现。→ 新增单元测试直接从 SKILL.md 读表比对。

## 二、本 PR 的改动

| 文件 | 内容 |
|---|---|
| `scripts/seedancer_calc.py` | 新增。零依赖计算器：`smin` / `dialogue` / `check-group` / `models`，支持 `--json`，退出码 0/1/2 |
| `SKILL.sh` | 重写。解析请求中的时长与画幅；超 15s 预警；`--help`；计算子命令委托给计算器；原有调用方式与退出码保持兼容 |
| `tests/test_calc.py` | 新增。13 个用例，含"SKILL.md 表格 ↔ 计算器常量"防漂移检查 |
| `.github/workflows/consistency.yml` | 新增。push / PR 时跑一致性检查、攻击测试、单元测试、SKILL.sh 冒烟 |

未改动 SKILL.md、references、版本号，因此 V1–V4、I1–I3、A1–A4、K1 等检查不受影响。

## 三、建议后续处理（未在本 PR 修改）

1. **运镜三要素口径冲突**："运镜功能表"一节写作「动机 · 方向 · 落点」，而权威定义（主动运镜三要素）是「起始观察点 · 运动轨迹方向 · 停止结果」。建议统一为后者，并把该节与"关键规则"中重复的条目（缓慢 ≥3s、≤2 个分量、逗号规则）合并。
2. **景别 ↔ 焦段表不严谨**：景别由机位距离与焦段共同决定，"特写 = 121–200mm"这类一一对应会误导模型。建议把列名改为"常用焦段（参考）"并加注。
3. **术语表最短时长不一致**：拉远 ≥3s 而推近 ≥1s，建议与 camera-design 参考文档对齐。
4. **简介仍是更新日志口吻**（"v7.0.0 新增…"）。建议改写为当前能力描述，版本历史留给 CHANGELOG。
5. **分组硬门表重复了模型时长上限**，而正文声明平台限额参考文档是唯一权威。建议在表下注明"以权威文件为准"，并核实 Seedance 2.5 / 30s 的出处。
6. **frontmatter `platforms` 不全**：description 提到 Wan、GPT Image、Seedream，但 `platforms` 只有 5 项。
7. **重复的「📎 加载」行**：多处与加载表重复，个别位置错位（如运营循环中加载失败码文档），可精简以腾出 K1 体积预算。
8. **在 SKILL.md 中引用计算器**：建议在"台词容量预检系统"与"镜头密度四道门"中各加一行"可运行 `./SKILL.sh check-group …` 验算"。为避免体积和锚点风险，本 PR 未改动。
